# Обновления из Cloud Hub

Начиная с 0.5.0, **Обновления → Скачать обновление → Установить и перезапустить**
выполняет весь цикл внутри приложения. На 0.4.2 и старше нужен один обычный запуск
установщика 0.5.0. Автопроверка ищет стабильный релиз при запуске и раз в сутки;
она не скачивает и не запускает установщик без нажатия пользователя.

## Загрузка и установка

1. GitHub Releases API предоставляет версию, текст изменений и точные имена
   установщика `CloudIsland-Setup-X.Y.Z-win-x64.exe` и `SHA256SUMS.txt`.
   Черновики, предварительные версии, посторонние репозитории, дубликаты активов
   и переход на предыдущую версию не предлагаются.
2. Загрузка работает вне потока интерфейса; частота прогресса ограничена.
   HTTPS разрешён только для GitHub и его серверов активов. Файл сначала
   сохраняется как `.part`. Размер ограничен 256 МБ. Проверяются заголовок PE,
   точный размер, SHA-256 из релиза и digest GitHub, когда он присутствует.
   Контрольная сумма проверяет целостность; это не цифровая подпись издателя.
3. «Установить» снова проверяет файл и создаёт отдельную копию текущего EXE как
   помощника в папке обновления. Он проверяет задание и путь исходного процесса,
   просит экземпляр текущего пользователя закрыться через локальный IPC и ждёт
   завершения как GUI, так и загрузчика PyInstaller.
4. После сброса заметок и настроек сохраняется снимок папки данных без рекурсии
   в `updates` и `backups`, а также предыдущий EXE. Сами программы, файлы и папки,
   на которые ссылаются группы, не копируются и не перемещаются.
5. Inno Setup запускается без мастера, без перезагрузки Windows и с `/TASKS=`:
   собранный с рабочего стола ярлык не появляется заново. Сохраняются путь
   существующей установки и запись автозапуска. Переносная версия переходит на
   `%LOCALAPPDATA%\Programs\Cloud Island` с общей прежней папкой данных.
6. Новая программа проходит `--self-test` с проверкой версии, Qt и WinRT, затем
   открывает страницу результата. Помощник ждёт ответа нового экземпляра по IPC.

Параметры установщика соответствуют [документации Inno Setup](https://jrsoftware.org/ishelp/topic_setupcmdline.htm).
Загрузку можно отменить. Готовый файл можно оставить на потом; фоновая проверка
не сбрасывает его. Восстановление текущей версии использует тот же проверенный
цикл. Во время установки нужен доступ на запись в папку программы и данных.

## Данные и таймер

Данные находятся в `%LOCALAPPDATA%\Cloud Island`. Группы и собственные копии
ярлыков, заметки, параметры и раскладка сохраняются. Оставшееся время таймера
передаётся только на обновление: активный отсчёт учитывает прошедшее время,
пауза удерживает остаток, закончившийся за установку таймер запускает обычную
реакцию завершения. Обычный полный выход по-прежнему останавливает таймер.

Перед обновлением создаётся папка `backups/before-<версия>-<время>-<идентификатор>`.
Кнопка **Открыть резервную копию** доступна после установки. Файлы загрузки,
`handoff.json`, `install.log` и диагностический отчёт лежат в `updates/<версия>`.
Копии и кэш не удаляются автоматически; их можно удалить после проверки версии.

## Если установка не завершилась

Помощник записывает понятный результат в `update-result.json`. Если приложение
уже было закрыто и новая версия не работает, он пытается вернуть предыдущий EXE
и открыть его. Внешний сбой Windows, блокировка файла или аварийное завершение
помощника могут потребовать повторного запуска установщика вручную. Полный
снимок пользовательских данных сохраняется; автоматического отката данных нет.
Чтобы вернуть данные из копии, закрой Cloud Hub и перенеси нужные файлы обратно
в папку данных. Не копируй `previous-CloudIsland.exe` в папку данных.

## Проверки

`tests/test_update_installation.py` проверяет адреса, релизы, контрольные суммы,
обрезанный/слишком большой файл, отмену с немедленной повторной попыткой,
ошибку сети, изменение файла после проверки, валидацию помощника, снимок данных,
ошибку установщика и восстановление EXE, а также перенос состояния таймера.
`tests/test_hub_design.py` проверяет интерфейс, клавиатуру и передачу данных.
`tools/check_hub_design.py` создаёт реальные изображения всех страниц и состояний
в изолированной папке данных; сетевые результаты в нём являются фикстурами.
