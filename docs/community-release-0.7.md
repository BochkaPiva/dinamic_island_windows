# Cloud Hub 0.7 / сообщество Nelviro

Дата: 19.10.2026. Новая модель: бесплатное открытое приложение и дополнительные
возможности за членство в бесплатном Telegram-канале, без платных лицензий.

## Что доступно

| Без входа | После подписки на @Nelviro |
| --- | --- |
| Нынешний Dynamic Island: музыка, календарь, таймер и заметки | Дополнительные группы рабочего стола |
| Поиск и локальные инструменты | Архитектура для будущих дополнительных модулей |
| Две активные группы | Будущие варианты оформления; сейчас не выдаются за готовые |

Практический общий предел групп в текущем интерфейсе — 30, чтобы панели не
перегружали рабочий стол. Его можно пересмотреть отдельно. Слово «безлимит»
не используется как обещание бесконечного количества окон.

При завершении расширенного доступа дополнительные группы не удаляются.
Все остаются в редакторе, их ярлыки можно открыть или перенести. На рабочем
столе показываются первые две. Кнопка «На рабочий стол» делает выбранную группу
одной из активных. Создать третью новую группу без подписки нельзя.

## Подключение

1. В «Сообществе» нажать «Подключить Telegram».
2. В @nelviro_bot открыть канал, подписаться и нажать «Проверить подписку».
3. Вернуться в приложение: подключение завершится автоматически.

Яндекс ID, почта, пароль, номер телефона и платёжные данные не требуются.
Активный сервер не предоставляет старые маршруты Яндекса, OAuth и оплаты.
Старый код сохранён как архивная линия с отдельным URLConf для регрессионных
тестов. Модули account_ui/account_client исключены из desktop-сборки.

Клиент доказывает владение запросом через одноразовый секрет и его SHA-256
challenge. В ссылке бота нет этого секрета. Telegram-кандидат поступает только
из проверенного события бота. Клиент автоматически завершает обмен, доказывая
владение запросом на том же компьютере. Повтор после потери ответа не создаёт новое устройство.

Секрет установки хранится через Windows DPAPI и ограничен источником сервиса.
На сервере хранится его контрольная сумма. Telegram ID не входит в подписанное
разрешение. Токен бота и закрытый ключ в EXE не передаются.

## Постоянная подписка

- Сервер принимает события изменения членства; бот должен быть администратором.
- Каноническая сверка выполняется при запросе разрешения, с кэшем до 6 часов.
- Клиент перепроверяет доступ в фоне, без ожидания сети в GUI; после ошибок
  делает паузу. Ожидание подключения к боту опрашивается только в этом сценарии.
- До 72 часов от последнего подтверждения допускается офлайн-работа расширения.
- Подтверждённая отписка даёт 24 часа, после чего остаётся базовый доступ.
- Если членство никогда не подтверждалось, льготный расширенный доступ не выдаётся.
- Повторная подписка восстанавливает расширенные возможности после проверки.

Открытый код можно изменить и собрать самостоятельно, включая изменение
проверки членства. GPL-права на модификацию не ограничиваются правилами
официальной сборки. Доступ не привязан к донатам.

## Фактический статус подключения

Bot API подтвердил @nelviro_bot и канал @Nelviro, ID -1004359060579.
Бот имеет статус администратора. Закрытые данные находятся вне checkout.
Локальный API и приём событий запущены только для проверки на ноутбуке.
Публичный HTTPS-адрес и постоянная база данных пока не развёрнуты.

Установщик 0.7.0 поэтому является предварительной сборкой: базовые функции
доступны, но публичный адрес активации ещё не встроен. Не объявлять его готовым
интернет-сервисом и не обещать подключение с другого ПК до развёртывания.

Решение о production-хостинге остаётся за владельцем. Для Vercel используются
webhook и внешняя PostgreSQL-база; long polling — отдельный вариант локального
или VPS-запуска, одновременно с webhook его не запускают.

## Vercel

Технически Django API и webhook совместимы с платформой. Постоянная локальная
SQLite-база в функциях не поддерживается; нужна внешняя PostgreSQL-база.
Закрытый ключ задаётся защищённой multiline-переменной COMMUNITY_SIGNING_KEY_PEM,
не загружается как часть репозитория или сборки. Производственный проект должен
принимать webhook без Vercel Deployment Protection, с проверкой собственного
секрета заголовка. Обычный пользователь не должен проходить вход в Vercel.

На Hobby разрешены некоммерческие личные проекты; добровольные донаты явно
исключены из определения коммерческого использования в Fair Use. Это не
означает обещания бессрочного бесплатного обслуживания или разрешения продавать
расширенный доступ на Hobby. Дальнейшая реклама/продажи требуют новой проверки.

Российского compute-региона в опубликованном списке Vercel нет. Связанные
Telegram ID и устройства требуют оценки правил обработки персональных данных,
размещения базы и трансграничной передачи до публичного запуска. Возможность
проверять канал не является самостоятельным юридическим разрешением.

Источники, проверенные 19.10.2026:

- https://vercel.com/docs/frameworks/full-stack/django
- https://vercel.com/docs/limits/fair-use-guidelines#commercial-usage
- https://vercel.com/kb/guide/is-sqlite-supported-in-vercel
- https://vercel.com/docs/regions
- https://www.consultant.ru/document/cons_doc_LAW_61798/78b773a28f3ad19eb234697b20ab1d48c09f748a/

Обязательность канала только для дополнительных функций не доказывает
автоматически неприменимость правил авторизации. Исследование не установило
правовую квалификацию конкретной схемы. Проверка этой части остаётся отдельной
задачей перед запуском; приложение не показывает утверждения «всё законно».

## Roadmap

1. Завершить локальное подключение реального пользователя и проверить переход
   базовый → расширенный → базовый без потери файлов и групп.
2. Выбрать размещение, постоянную PostgreSQL-базу и HTTPS-адрес, определить
   требования к данным. Отдельно согласовать расходы, если они понадобятся.
3. Развернуть webhook, проверить конкурентные операции на PostgreSQL, бэкап,
   восстановление, лимиты запросов, очистку истёкших запросов и недоступность
   Telegram. На Vercel не использовать память экземпляра как постоянную базу.
4. Встроить публичный адрес в подписанную сборку, проверить два ПК, сон,
   отсутствие сети, отписку и возврат. Опубликовать версию вместе с исходниками.
5. Доработать общий дизайн и расширения по реальным запросам, сохраняя нынешний
   остров бесплатным. Не выпускать семь отдельных приложений одновременно.
6. Подключить необязательную поддержку проекта и отчёты о расходах, отдельно
   проверив условия выбранного сервиса для самозанятого.
