# Community API v2 — без Яндекс ID

Активный URLConf: cloud_accounts.urls. Исторические аккаунты и платежи доступны
только через cloud_accounts.legacy_urls в архивных тестах; production не
экспортирует их маршруты. Текущий продукт не требует почты или пароля.

## API

Все тела JSON, ответы no-store. Секреты не передаются в query string.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | /api/v2/community/config | Возможность подключения и базовые лимиты |
| POST | /api/v2/community/pairings | product=cloud-hub, UUID установки, S256 challenge |
| POST | /api/v2/community/pairings/{uuid}/status | verifier, ожидание подтверждения в боте |
| POST | /api/v2/community/pairings/{uuid}/confirm | verifier и ожидаемый Telegram ID |
| POST | /api/v2/community/permit | Bearer-секрет установки, подписанное разрешение |
| POST | /api/v2/community/disconnect | Отзыв подключения только этого устройства |
| POST | /hooks/telegram | События Telegram с секретом заголовка |

Повтор confirm с тем же proof после потери ответа идемпотентен. Чужой Telegram
не может перепривязать уже связанную установку. TTL подключения — 10 минут,
секрета устройства — 90 дней. После его истечения нужна новая привязка через бота.

В базу не отправляются локальные документы и группы. Точные сроки удаления
отключённых устройств и резервных копий, а также политика обработки данных
должны быть утверждены до публичного запуска. Секреты бота, Django и ключ
подписи находятся только в защищённом окружении сервера.

## Локально

Установить зависимости из requirements.txt, задать переменные из .env.example
через окружение процесса (файл автоматически не загружается), выполнить:

```text
python manage.py migrate
python manage.py runserver 127.0.0.1:8000 --noreload
python manage.py telegram_poll
```

Последняя команда — второй процесс при отсутствии webhook. Она не печатает
содержимое сообщений. Не запускать два получателя для одного бота. Команда
не удаляет существующий webhook самостоятельно.

SQLite применяется для локальной проверки. Production-конфигурация требует
PostgreSQL, сильного DJANGO_SECRET_KEY, явных HTTPS origin/hosts и полного
набора параметров бота и Ed25519-ключа. Перед выпуском нужны проверки
конкурентных запросов на PostgreSQL и контроль лимитов/хранения.

## Vercel

Исходники Django совместимы с HTTP-функциями; корень проекта — server/.
Постоянная PostgreSQL-база должна быть подключена отдельно, близко к выбранному
региону. Не использовать локальный sqlite-файл или память функции для запросов
привязки и статусов. Миграции выполняются отдельно один раз при развёртывании,
не на каждом HTTP-запросе и не каждым экземпляром функции.

Настроить CLOUD_ENV=production, PUBLIC_ORIGIN, ALLOWED_HOSTS, PGHOST/PGPORT/
PGDATABASE/PGUSER/PGPASSWORD/PGSSLMODE и переменные COMMUNITY_*/TELEGRAM_*.
COMMUNITY_SIGNING_KEY_PEM — защищённая multiline-переменная, PRIVATE KEY не
помещается в проект. .vercelignore исключает локальные ключи и базы.

В production использовать webhook по общедоступному HTTPS-адресу
/hooks/telegram и secret_token. В setWebhook явно указать allowed_updates:
message, callback_query, chat_member. Приёмник сам проверяет
X-Telegram-Bot-Api-Secret-Token. Токен бота нельзя вставлять в публичный URL
webhook, клиентское приложение, текст коммита или инструкции для пользователей.

Если Deployment Protection требует входа Vercel, Telegram и Windows-клиент не
смогут обращаться к API. Проверять публичный endpoint из независимой сессии.
Перед включением сохранить прежнюю конфигурацию webhook для отката; рабочий
канал событий нельзя заменять непроверенным preview-адресом.

Технический запуск 19.10.2026: https://nelviro-community.vercel.app,
проект Vercel nelviro-community, регион функции fra1, Neon Free во Франкфурте.
Webhook переключён на этот адрес, long polling на ноутбуке не используется.
Проверка /api/v2/community/health контролирует соединение с таблицей устройств
и возвращает только готовность, без статистики пользователей и деталей ошибок.
69 серверных тестов прошли на PostgreSQL, включая две проверки конкурентности;
ещё два теста проверяют безопасный ответ health. Миграции применены отдельно.

Вопросы хранения данных в РФ и правовой квалификации условия подписки не
решаются настройкой Vercel. Техническое размещение не заменяет правовую оценку.
